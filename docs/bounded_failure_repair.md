# 失败题的通用受限修复

不按题号、表名或特定标签分支。仅在正常执行已失败时进入修复。

## 结构几何补丁

1. 原有确定性结构修复失败后，代码通过矩形交集找出所有冲突单元格索引。
2. 给模型完整页面、原结构、允许修改的索引及具体错误。
3. 模型只返回 JSON updates，每项包含 index、row、col、rowspan、colspan。
4. Pydantic 拒绝文本修改、额外字段、重复索引，以及非冲突单元格修改。
5. 在原结构的副本上应用补丁，再检查完整结构。不得增加/删除单元格，不改变整表尺寸。
6. 每题最多一次补丁；失败后不会因为这个补丁再次触发整题视觉重答。

`recovery.max_structure_patches: 0` 可关闭，默认 1。没有完整页面或模型不支持该方法时
保持原有失败行为。补丁不保证视觉识别正确，只保证修改范围和结构协议。
如果错误涉及文字、缺失单元格或全局布局，应保留失败，不扩张补丁权限。

日志保留原 Evidence；补丁响应在 `patch_structure.raw_output`，最终结构在 tool_result。
原始候选与最终答案不相互覆盖，便于审计。

## 计算协议补全

计算题在已有视觉恢复中仍缺少 Evidence/Operation 时，最多额外请求一次协议补全，
要求从当前图片重新读取操作数，禁止把上次模型的 answer 当作操作数或最终结果。
补全后仍使用现有 Python 执行器；不接受只有 answer 的响应。
成功补全的原始响应记录在 warning 中，用量合并统计。关闭视觉恢复也不会进入这一补全路径。

## 验证

依赖不变：`pip install -e '.[dev]'`；运行 `pytest -q` 和 `ruff check src tests`。
测试覆盖局部补丁不改文字/非冲突格/源对象、拒绝越权/空/重复/仍重叠补丁，
以及流水线记录补丁与计算协议重试的用量。

旧全量日志及 v5 提交文件保持不变。复跑结果使用独立日志；仅把 status=success 且
没有格式兜底的候选作为替换来源。正确率需重新评测，不能从协议通过推断。
