# 结构路径：范围、上下文与冲突诊断

本轮只修正通用流程，不按题号决定表格尺寸、跨度或保留哪些单元格。

## 统一范围

沿用项目现有 `submission_contract.md` 的语义：完整目标表格行列数、
完整目标表格的零基坐标，以及题目要求范围内的 cells。本轮没有重新定义比赛协议，
也没有从历史答案反推坐标口径。若后续官方说明与当前项目约定不同，须单独核实后调整。

共享说明位于 `structure/contract.py`，结构专家和区域定位器同时使用：
明确识别上下文与输出范围，禁止裁剪图重新编号、混入其他表格或因重复展示而重复输出。

## 补读输入

结构专家收到：完整页面（保留全部已有页面）+ 清晰的用途说明 + 高清局部图。
OCR 仍只处理局部图；普通抽取的补读输入保持不变。
这可能增加结构补读调用的图像 token 和耗时；不增加调用轮数，也不自动补齐缺失页面。

## 冲突诊断

几何验证遇到首个冲突即报告，不宣称已枚举全部冲突：

- 越界：单元格索引、文本、行列覆盖范围、表格尺寸。
- 重叠：两个单元格的索引、文本、覆盖范围及首个重叠坐标。
- 范围使用左闭右开区间，坐标从 0 开始。

详细信息传入 StructureRepairError 和运行日志的 recovery_attempts.reason / error_message。
修复器去重后的错误会注明索引对应去重后的 cells，避免误认原始数组索引。
错误文本最多展示每格前 120 字；原始完整内容仍在 Evidence 日志中。

不新增缩短跨度、删除冲突单元格、移动坐标的自动规则；已有完全重复项去重与最小尺寸
扩展保持不变。程序不会仅为了通过校验而选择某个单元格作为正确答案。
本轮也未引入模型局部修复回路或新的内部坐标表示。

## 验证与使用

无新增依赖；新环境使用 `pip install -e '.[dev]'`。

```bash
pytest -q
ruff check src tests
table-qa run --ids 25,32,43,51,549,569,589,729,739,759,859 --no-resume --workers 4 \
  --log-path outputs/logs/structure_context_smoke.jsonl \
  --output outputs/submissions/structure_context_smoke.xlsx
```

上述 ID 仅用于复测多个已有样本，不参与生产逻辑。测试覆盖上下文保留、非结构路径不变、
共享范围合同、合法局部结构保持全局坐标、重叠与越界诊断、修复失败不修改原始输入。
线上结果需要人工核对恢复范围和合并关系；校验通过不等于结构正确。
